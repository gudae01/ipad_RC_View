# 구조와 영상 상태

## 데이터 흐름

```text
AVCaptureDevice.DiscoverySession(.external)
  → AVCaptureDeviceInput
  → AVCaptureSession
      ├─ AVCaptureVideoPreviewLayer → 화면 표시
      └─ AVCaptureVideoDataOutput → 프레임 도착 시각/개수만 관측

CaptureService → CaptureSnapshot → @MainActor ViewerModel → SwiftUI
```

실기기는 `ExternalCaptureService`, 시뮬레이터는 `MockCaptureService`를 선택합니다. 시뮬레이터 분기는 컴파일 대상으로 구분하므로 실기기에서 장치를 찾지 못했다고 데모로 전환하지 않습니다. 테스트는 서비스를 주입할 수 있습니다.

## 스레드와 세션 수명

- 탐색, 권한 후 처리, 구성, 시작/중지, 장치 알림, 데이터 출력 콜백, 프레임 감시는 한 직렬 큐에서 실행합니다.
- UI에는 값 타입 스냅샷만 전달하고 메인 큐에서 게시합니다.
- PreviewLayer는 UIKit 뷰의 레이어로 관리합니다. 화면 표시 변환만 적용하고 캡처 세션은 입력 서비스가 소유합니다.
- 장치 연결/해제 알림 후 다시 DiscoverySession을 만들고 새 장치 객체를 검색합니다. 이전 선택은 uniqueID로 찾되 다른 장치로 몰래 전환하지 않습니다.
- 앱 비활성화 시 캡처를 중지하되 사용하던 장치 ID·입력 형식·수동 시작 의도를 유지합니다. 복귀 시 권한/장치를 다시 확인하고 USB가 준비되는 동안 제한된 재시도로 자동 복구합니다. 배경에서 카메라를 유지하지 않습니다.
- 시스템 세션 중단/복구와 미디어 서비스 초기화 오류를 처리합니다. 자동 복구를 무한 반복하지 않고 실패 안내와 수동 재연결을 제공합니다.
- 이미 구성한 세션은 해당 입력 FPS의 첫 프레임 대기 시간을 준 뒤 복구를 시도합니다. 실제 프레임 수신 시 재시도를 끝내며 다시 비활성화되면 중단합니다. 발견 실패만으로 사용자의 수동 시작 의도를 자동 미리보기 설정으로 덮지 않습니다.
- OS가 멀티태스킹 카메라 접근을 지원한다고 보고할 때만 해당 옵션을 켭니다. 기기/OS에서 지원하지 않는 창 모드는 입력이 중단될 수 있으며, 이 경우 iPad 앱 창을 전체 화면으로 넓혀 확인합니다. 추가 VoIP 배경 모드나 별도 권한을 요구하지 않습니다.

Apple은 일반적인 백그라운드 카메라 사용 중단과 전경 복귀 동작을 [AVCaptureSession 문서](https://developer.apple.com/documentation/avfoundation/avcapturesession/interruptionreason/videodevicenotavailableinbackground)에 설명합니다. 여기서 자동 복구는 잠금 해제 후 앱으로 돌아왔을 때의 동작이며, 화면이 꺼진 동안 계속 영상을 수신한다는 뜻이 아닙니다.

## 상태의 의미

| 상태 | 확인한 사실 / 사용자 행동 |
|---|---|
| 카메라 권한 확인 중 | 권한 응답 대기 |
| 카메라 접근 권한 필요 | 거부/기기 제한. 설정 확인 |
| 연결 대기 | 장치 없음, 여러 장치 선택 필요 또는 자동 미리보기 꺼짐 |
| 재연결 중 | 장치/형식/세션 재구성 |
| 프레임 대기 | 장치 입력을 구성했지만 아직 콜백 없음 |
| 프레임 수신 중 | 데이터 출력 콜백 도착 확인. 원본 HDMI 정상 여부는 모름 |
| 영상 입력 중단 | 설정된 시간 동안 새 프레임 없음 또는 시스템 중단 |
| 연결이 끊어졌습니다 | 외부 장치 해제/검색 결과에서 이전 장치 없음 |
| 미리보기 일시 정지 | 앱 비활성화 등으로 캡처 중지 |
| 영상 세션 오류 | 세션/형식 구성 또는 실행 오류 |

검은 픽셀, 정지된 풍경, `No Signal` 텍스트를 판독하지 않습니다. 같은 이미지가 반복되어도 새 프레임이 도착하면 프레임 수신 중입니다. 프레임 도착 중단은 USB 장치 분리와 다른 상태입니다.

수신이 중단되면 미리보기 위를 불투명 안내로 가립니다. 따라서 마지막 프레임을 계속 실시간 영상처럼 보여주지 않습니다. 앱 내부 픽셀 프레임을 저장하지 않습니다.

## 형식과 FPS

- `device.formats`와 `videoSupportedFrameRateRanges`에서 실제 해상도와 범위를 읽습니다.
- `VideoFormatPolicy`는 양수 크기의 UHD 3840×2160 이하, 최대 60fps만 선택 대상으로 허용합니다. 각 지원 범위의 끝점과 범위 안에 포함되는 일반적인 FPS를 사용하며 장치가 제공하지 않는 해상도/FPS를 추가하지 않습니다. 120fps 고정 형식을 임의의 60fps 형식으로 바꾸지 않습니다.
- 기본 선택은 높은 프레임률을 우선하고, 같은 프레임률에서는 높은 해상도를 선택합니다. 59.94fps와 60fps는 같은 우선순위입니다. 예: 4K60 → 1080p60 → 4K30, 4K59.94 → 1080p60. 이 순서는 실제 제공되는 후보 사이의 우선순위이며 특정 형식 지원을 보장하지 않습니다.
- 사용자가 선택한 지원 형식은 재연결 시 가능한 경우 유지합니다. 업스케일·프레임 보간은 하지 않습니다. 대역폭/부하로 수신이 불안정하면 연결 화면에서 더 낮은 해상도나 FPS를 선택해 비교합니다.
- 장치 잠금을 얻어 `activeFormat`과 프레임 간격을 설정합니다. 활성 설명은 적용된 장치 값에서 읽습니다.
- 설정 FPS와 **관측된 수신 FPS**는 다릅니다. 관측 FPS는 출력 콜백 개수를 단조 증가 시간 간격으로 나눈 값이며 첫 측정 전/중단 시에는 미측정으로 표시합니다.
- HDMI 원본의 해상도·조종기 모델·배터리·GPS는 캡처카드 이름에서 추측하지 않습니다.

## 낮은 추가 지연을 위한 선택

- PreviewLayer가 네이티브 캡처 영상을 표시합니다. 앱에서 재인코딩, 효과, CPU 픽셀 복사, 프레임 큐를 만들지 않습니다.
- DataOutput은 `alwaysDiscardsLateVideoFrames = true`이며 버퍼 내용을 읽지 않고 콜백 도착만 기록합니다.
- 비디오 데이터 출력 자체에도 장치/OS 처리 비용이 있으므로 실기기에서 부하·열·지연을 확인해야 합니다.
- 앱은 지연 수치를 표시하지 않습니다. 콜백 관측 간격/FPS는 처리 지연이나 전체 지연이 아닙니다.
- 전체 지연은 조종기/전송/HDMI/캡처카드/USB/iPad 표시를 포함합니다. 고속 카메라 등 외부 기준으로 실측해야 합니다.

## 표시 변환

- 외부 입력의 자동 미러링을 끄고 수평 반전을 비활성화합니다.
- 지원되는 경우 PreviewLayer 연결 회전각을 0으로 유지합니다. 기기 자세를 입력 영상 회전에 자동 적용하지 않습니다.
- 90도 회전 시 원본 폭/높이를 교환하여 aspect-fit 크기를 계산하고 표시 레이어만 회전합니다. 화면 채우기 분기와 저장된 맞춤 방식 설정은 사용하지 않습니다.
- 표시 비율 계산은 실제 포맷의 픽셀 종횡비와 clean aperture를 반영한 presentation dimensions를 사용합니다. 메타데이터의 해상도는 인코딩된 입력 크기를 그대로 표시합니다.
- 전체 화면 진입 시 확대율을 1로 초기화하여 전체 프레임을 표시합니다. 비율 차이로 생기는 여백은 검은색입니다. 사용자가 직접 핀치 확대하면 가장자리가 잘릴 수 있으며 초기화로 복귀합니다. 조작으로 원본 영상이나 드론 제어 신호는 바뀌지 않습니다.

## 저장과 권한

- UserDefaults: 자동 미리보기, 자동 전체 화면, 화면 꺼짐 방지, 맞춤 방식, 표시 회전.
- 연결 이력: 제한된 개수의 메모리 내 로컬 이벤트. 앱 종료 후 영구 로그를 저장하지 않습니다.
- 카메라 권한만 요청합니다. 마이크/사진/네트워크 API를 사용하지 않습니다.
- 캡처 화면은 저장/전송하지 않습니다. Apple 계정은 앱에 로그인하지 않으며 설치 도구에서만 사용합니다.
