# 검증 기록

확인일: 2026-11-10. 실행 환경: Windows / Python 3.13. Apple SDK와 Xcode 없음.

## 최초 버전에서 통과한 로컬 검사

- 프로젝트 생성과 `--check`: 체크인된 프로젝트/공유 Scheme이 현재 소스 목록과 일치.
- 프로젝트 검증: Swift 앱 소스 12개 참조, PBX 객체 참조, 테스트 참조, 카메라 권한, iPad 방향/대상/최소 OS, 에셋 파일, 앱 아이콘, 수동 워크플로 구조.
- IPA 패키징 Python 단위 테스트 **3개 통과**: arm64 시뮬레이터 바이너리 거부, 잘못된 CPU/파일 거부, Payload/체크섬 생성 및 프로비저닝 파일 혼입 거부.
- Git Bash `-n`: macOS 빌드 스크립트와 시뮬레이터 테스트 스크립트 문법 통과. 스크립트의 Xcode 명령을 실행한 것은 아님.
- Python 구문 검사, JSON 파싱, 문서의 상대 링크 확인.
- 다섯 시안 이미지 크기 확인 및 전체 시트 시각 검토: 가로 2388×1668 네 장, 세로 1668×2388 한 장.
- 캡처/UI/빌드 코드를 나누어 정적 교차 검토. 예상치 못한 세션 중지, 느린 프레임률 중단 오판, 뷰 재등장, 회전 비율/미러링, 전체 화면 버튼 탭 전파 경로 보완.

패키징 단위 테스트는 **합성 바이너리 fixture**를 사용합니다. 이 테스트의 작은 IPA는 실행 가능한 RC View가 아니며 배포하지 않습니다.

Windows 샌드박스에서 임시 디렉터리와 Git Bash 프로세스 시작이 제한된 검사는 권한을 허용한 재실행에서 통과했습니다. 앱 코드 오류로 인한 실패가 아니었습니다.

## 기존 버전의 사용자 확인

- 커밋 `5b2118b`의 `Build RC View IPA #1`: 제공된 화면에서 Success, 총 약 6분 6초, artifact 1개를 확인했습니다. 개별 Xcode 로그와 체크섬은 이 기록에서 검토하지 않았습니다.
- 사용자는 IPA 설치·앱 실행 후 iPad A16 + Lemorele 캡처카드에서 PC 영상이 표시된다고 보고했습니다. 마우스 움직임의 약간의 딜레이/버벅임도 보고했습니다.
- 캡처카드 정확한 모델, iPadOS 버전, 활성 형식, 관측 FPS, 전체 지연 시간은 아직 제공되지 않았습니다. 영상 표시 보고만으로 4K·60fps나 장시간 안정성을 확인한 것은 아닙니다.

## 최대 4K·60fps 변경

- 지원 범위 상한과 기본 선택 정책을 분리하고 `VideoFormatPolicyTests`에 4K/60fps 경계, 범위 밖·유효하지 않은 값, 59.94fps 우선순위, 1080p60과 4K30의 선택 사례 10개를 추가했습니다.
- 버전 1.1.0(빌드 2): Windows 프로젝트 재생성, 앱 Swift 소스 13개 참조 검증, 패키징 Python 테스트 3개, 정적 교차 검토와 `git diff --check`가 통과했습니다.
- 새 아이콘을 포함한 커밋 `6ed08fd`의 [GitHub Actions #3](https://github.com/gudae01/ipad_RC_View/actions/runs/42759059290)이 성공했습니다. Xcode 시뮬레이터 컴파일, XCTest 16개(프레임 감시 6개 + 형식 정책 10개), 기기용 Release 빌드 및 unsigned IPA 검증이 통과했습니다.
- 내려받은 artifact ZIP 체크섬이 GitHub의 digest와 일치하고 IPA 체크섬도 `SHA256SUMS.txt` 및 `BUILD-INFO.json`과 일치했습니다. 버전 1.1.0, 빌드 2, IPA 1,538,715바이트, SHA-256 `b2a249ae612d46a1123f0e0a7ee785e06210e27a3963cf55f75ee40456cd8adf`입니다.
- 지정된 아이콘 원본을 그대로 보관하고 1024×1024 RGB 에셋으로 변환했습니다. 아이콘/프로젝트 로컬 검사와 IPA의 arm64/iOS·실행 권한 검증도 통과했습니다.
- 수동 실행 외에 앱·테스트·빌드 파일 변경 PR을 검증하며 예약 실행과 일반 push 실행은 없습니다. 이 검증 기록 갱신은 문서만 변경하므로 빌드를 반복하지 않습니다.
- 실제 4K·60fps 수신 여부와 커서 움직임 개선은 실기기에서 비교해야 합니다. HDMI 4K 입력/패스스루 지원만으로 USB 4K 캡처 출력을 확인할 수 없습니다.

## 화면 복귀와 새 아이콘 검증 — 1.2.0

- 원본 비율 전용 변경 `2344c26`은 [빌드 #4](https://github.com/gudae01/ipad_RC_View/actions/runs/42762856775)에서 XCTest 16개와 기기용 빌드를 통과했습니다.
- 새 파란 아이콘·잠금 해제 후 자동 복구를 포함한 `bdad405`는 [빌드 #5](https://github.com/gudae01/ipad_RC_View/actions/runs/42766099094)에서 XCTest **22개**(프레임 감시 6, 형식 정책 10, 복구 정책 6)와 기기용 Release 빌드를 통과했습니다.
- 복구 정책 검사는 재시도 횟수 제한, 저FPS 첫 프레임 대기, 늦은 watchdog, 중복 오류, 수신·비활성화 취소, 새 복귀 주기 재시작을 포함합니다. 실제 USB 하드웨어의 잠금/해제 시험을 대체하지 않습니다.
- 로컬 프로젝트 검사: Swift 앱 소스 14개, 버전 1.2.0(빌드 4), 아이콘·공유 Scheme·권한 검증 통과. 지정된 파란 아이콘 원본과 보관본의 SHA-256도 일치합니다.
- 다운로드한 IPA는 **1,734,717바이트**, SHA-256 `3944218b4972466b209a122980107c0fd6680cdaab768d495eced32cafd545af`입니다. artifact ZIP의 GitHub digest, IPA의 SHA256SUMS/BUILD-INFO, 로컬 arm64/iOS 구조 검증이 일치·통과했습니다.
- 이 기록 갱신은 문서만 변경하므로 추가 빌드를 실행하지 않습니다.

## 아직 검증하지 않은 항목

- 새 IPA의 iPad 설치와 실기기 입력.
- 화면 잠금·해제 후 실제 iPad A16/Lemorele USB 장치의 자동 복구와 필요한 시간.
- Sideloadly 무료 서명 7일 갱신.
- 장치별 최대 USB 출력 해상도/FPS와 iPad A16 연결 조건에서의 안정성.
- DJI RC 2 영상 출력 여부 및 전체 경로의 지연.
- 실기기 화면/회전/장시간 발열/프레임 정체.

클라우드 빌드가 통과한 후에도 `TESTING.md`의 실기기 체크리스트를 별도로 실행해야 합니다.
