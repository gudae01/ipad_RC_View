# 검증 상태와 실기기 테스트

## 현재 상태

**새 아이콘과 최대 4K·60fps 변경을 포함한 커밋 `6ed08fd`는 Actions #3에서 빌드와 XCTest 16개를 통과했습니다. 이전 버전의 iPad PC 영상 표시는 사용자 자료로 확인했으며 새 버전의 실기기 시험은 별도입니다.** 검사 결과는 `docs/VALIDATION.md`에 기록합니다. 설계 PNG는 실제 실행 화면이 아닙니다.

| 항목 | 검증 수단 | 현재 구분 |
|---|---|---|
| 소스/프로젝트/권한/에셋/공유 Scheme 정합성 | Windows Python 검사 | 로컬 결과 참조 |
| SwiftUI/AVFoundation 컴파일 | GitHub Actions Xcode | 커밋 `6ed08fd` 시뮬레이터·기기 빌드 성공 |
| 프레임 감시/상태 단위 테스트 | GitHub Actions iPad 시뮬레이터 | 6개 통과, 실패 0 |
| 최대 해상도/FPS·기본 형식 선택 단위 테스트 | `VideoFormatPolicyTests` | 10개 통과, 실패 0 |
| 시뮬레이터 UI | 명시적 모의 서비스 | 실제 UVC 테스트 아님 |
| IPA 서명/설치 | Windows Sideloadly + 개인 iPad | 기존 버전 설치·실행 사용자 보고 |
| 장치 연결·형식·FPS·회전·부하 | 실제 iPad + UVC 캡처카드 | PC 영상 표시 확인. 커서 버벅임 보고, 수치·원인 미확인 |
| DJI RC 2 영상 출력/전체 지연 | 실제 조종기·펌웨어·어댑터 | 미확인 |

구현이 존재한다는 것과 해당 환경에서 동작을 확인했다는 것을 구분합니다. CI 성공 이후에도 물리 UVC/발열/지연은 검증되지 않습니다.

## 체크리스트

확인한 범위만 체크합니다. 아래 기존 버전 확인은 이번 4K·60fps 변경의 통과를 의미하지 않습니다.

### 설치와 권한

- [x] 기존 커밋 `5b2118b`: Actions 성공 및 artifact 1개 생성 화면 확인. 개별 로그·체크섬은 별도 확인 필요.
- [x] 기존 버전: 사용자 iPad 설치·실행 및 PC 영상 표시 보고.
- [x] 이번 변경: Actions #3의 iPad용 빌드/테스트가 통과하고 새 IPA 및 SHA-256이 생성됨. 다운로드 체크섬도 일치.
- [ ] 이번 변경: 새 IPA를 Sideloadly로 설치하여 실행.
- [ ] 최초 실행에서 카메라 권한을 허용하면 장치 탐색 진행.
- [ ] 거부하면 권한 안내 및 설정 이동. 내장 카메라/데모로 전환되지 않음.
- [ ] 설정에서 다시 허용 후 앱 복귀 시 권한/장치 재확인.
- [ ] 마이크·사진·네트워크 권한 요청 없음.

### 연결과 재연결

- [ ] 캡처카드 없이 시작: 연결 대기, 영상/가짜 장치/FPS 없음.
- [ ] 장치 연결 상태에서 시작: 자동 미리보기 켜짐 + 한 장치이면 시작.
- [ ] 앱 실행 중 장치 연결: 실제 장치 이름과 프레임 상태 표시.
- [ ] 프레임이 오기 전에는 프레임 대기, 이후에만 수신 중.
- [ ] 장치 분리: 연결 해제 표시. 마지막 화면이 실시간처럼 남지 않음.
- [ ] 같은 장치 재연결: 새 장치 객체로 세션 복구.
- [ ] 여러 장치 연결: 처음에는 사용자가 선택. 선택 장치가 사라져도 다른 장치로 자동 전환되지 않음.
- [ ] 자동 미리보기 꺼짐: 연결만으로 시작하지 않으며 목록 선택/재연결로 수동 시작 가능.
- [ ] 장치 연결/해제/오류 이력이 알림 시트에 표시됨.
- [ ] 케이블을 유지하고 iPad 화면을 잠근 뒤 잠금 해제·앱 복귀: 선을 다시 꽂지 않아도 동일 장치·입력 형식으로 수신 재개.
- [ ] USB 장치가 늦게 깨어나는 경우 자동 재검색을 확인하고 첫 프레임 이후 재연결이 반복되지 않음.
- [ ] 자동 미리보기 OFF에서 수동으로 시작한 영상도 잠금 해제 후 복구되며, 아직 수동 시작하지 않은 장치는 자동으로 시작하지 않음.
- [ ] 자동 복구 중 다시 화면을 잠그면 재시도가 중단되고 다음 복귀에서만 다시 시도.
- [ ] 실제 장치 분리·지원하지 않는 형식·지속적인 OS 중단에서는 무한 세션 재생성 없이 상태와 수동 복구 안내 표시.

### 신호와 형식

- [ ] HDMI를 분리하고 USB만 연결: 카드가 No Signal을 송출하면 수신 중으로 표시하되 정상 원본 신호라고 주장하지 않음.
- [ ] 정지 화면/검정 화면 원본에서도 프레임 도착이 계속되면 연결 해제로 오인하지 않음.
- [ ] 프레임 콜백이 멈추면 입력 중단으로 표시. 물리 USB 해제와 구분.
- [ ] 지원 형식 목록을 실제 장치와 비교. 없는 해상도/FPS가 선택지에 없음.
- [ ] 최대 UHD 3840×2160·60fps 범위만 표시. 4K60 지원 카드에서는 해당 형식을 선택할 수 있고, 미지원 카드에는 가짜 4K60 항목이 없음.
- [ ] 4K60/1080p60/4K30을 모두 지원하면 자동 4K60, 4K30/1080p60만 지원하면 자동 1080p60 선택. 4K59.94와 1080p60이면 4K59.94 선택.
- [ ] 4K60 미지원 시 실제 지원 후보 중 기본 형식을 선택. 1080p60도 지원되지 않으면 해당 항목을 만들지 않음.
- [ ] 지원 형식 변경 후 활성 형식/실제 관측 FPS가 갱신됨.
- [ ] 형식 적용 실패 시 오류 안내 후 지원되는 다른 형식 또는 재연결로 복구.
- [ ] 매우 낮은 지원 FPS에서도 정상 프레임 간격을 중단으로 오인하지 않음.
- [ ] 장치의 설정 FPS와 관측 FPS를 구분하고 미측정 시 숫자를 만들지 않음.

### 표시와 수명

- [ ] 글자가 있는 HDMI 테스트 화면으로 좌우 반전이 꺼져 있는지 확인.
- [ ] 기본 비율 유지에서 네 모서리가 보이고 영상이 늘어나지 않음.
- [ ] 일반/전체 화면/설정에 화면 채우기 선택지가 없고, 이전 버전의 채우기 설정이 남아 있어도 원본 비율로 표시됨.
- [ ] 확대 후 전체 화면 진입(일반 버튼/자동 진입/접근성 동작) 시 1배로 초기화되어 네 모서리가 보임.
- [ ] 핀치 확대/축소가 작동하고 최소 확대율 아래로 축소되지 않음.
- [ ] 0/90/180/270도 회전 각각에서 비율과 방향 확인.
- [ ] 가로/세로 전환, Split View/Stage Manager 창 크기 변화에서 영상 왜곡 없음.
- [ ] 대표 가로 화면에서 메인 조작을 위해 스크롤할 필요 없음.
- [ ] 전체 화면 진입/종료, 터치 조작부, 약 3초 숨김, 다시 터치로 표시.
- [ ] 전체 화면에서 분리/중단 안내가 보이고 종료 버튼 접근 가능.
- [ ] 자동 전체 화면 설정이 수신 시작에 적용됨.
- [ ] 앱 비활성화/복귀 및 다른 카메라 앱의 중단/복구를 확인.
- [ ] 화면 꺼짐 방지는 수신 중/앱 활성 상태에만 적용되고 나가면 해제.
- [ ] 큰 글씨/VoiceOver에서 버튼의 의미와 상태를 알 수 있음.

### 장시간과 지연

- [ ] 30분 이상 입력: 프레임 정체, 메모리 증가, 열, 배터리 기록.
- [ ] 지원되는 높은 해상도/FPS에서 부하를 비교하고 안정적인 설정 기록.
- [ ] 같은 PC 화면으로 지원되는 4K60·1080p60·720p60을 비교하고 활성 형식/관측 FPS/커서 끊김/발열을 기록. 지원하지 않는 모드는 건너뜀.
- [ ] 프레임 처리 지연 후 과거 프레임이 긴 시간 쌓여 재생되지 않음.
- [ ] 외부 고속 촬영으로 원본/아이패드 표시 시간 차이를 실측. 평균/범위/장비/조건 함께 기록.
- [ ] 앱의 수신 FPS를 전체 경로 지연으로 해석하지 않음.
- [ ] 7일 이내 무료 서명 갱신과 만료 후 재설치를 확인.
